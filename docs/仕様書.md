## 1. プロジェクト概要

### 1.1 目的

SEMI規格に準拠した SECS/GEM 通信のシミュレーション環境を提供する。  
半導体製造装置とホストコンピューター(PC)間の通信テストを、実機なしで検証できるツール。

### 1.2 適用規格

| 規格番号 | 規格名 | 内容 |
|----------|--------|------|
| SEMI E37 | HSMS (High-Speed Message Services) | TCP/IP 通信プロトコル |
| SEMI E5  | SECS-II | メッセージフォーマット |
| SEMI E30 | GEM (Generic Equipment Model) | 装置制御モデル |
| SEMI E87 | CMS (Carrier Management System) | キャリア管理 |

### 1.3 準拠レベル

**GEM Full Compliant** (SEMI E30 全必須機能実装)  
**E87 基本実装** (ポート/キャリア管理・通知)

### 2.4 DI 登録 (secs4net スタック)

secs4net v2.4.4 本体には DI 拡張が含まれないため、`SampleEqSim.Core` に登録ヘルパー
`Secs4NetServiceCollectionExtensions.AddSecs4Net<TLogger>(IConfiguration)` を実装している
(公式サンプル `samples/DeviceWorkerService` と同等)。両アプリの `App.OnStartup` から呼び出し、
以下を Singleton 登録する。

| サービス | 実装 | 説明 |
|---------|------|------|
| `ISecsConnection` | `HsmsConnection` | HSMS 接続 (TCP/IP)。コンストラクタで Socket を Bind する |
| `ISecsGem` | `SecsGem` | SECS-II メッセージ送受信 |
| `ISecsGemLogger` | `DeviceLogger` (各アプリ固有) | secs4net 内部ログのブリッジ |
| `SecsGemOptions` | (設定バインド) | `appsettings.json` の `secs4net` セクションをバインド |

> `ISecsConnection` と `ISecsGem` は別オブジェクトのため、接続状態イベント
> (`ConnectionChanged`) の購読・接続開始 (`Start`) は `ISecsConnection` 側で行う。

### 2.5 起動シーケンスと接続ライフサイクル

GEM モデル (`GemEquipmentModel` / `HostGemService`) は `IHostedService` として登録される。

```
App.OnStartup
  │ Host.CreateDefaultBuilder() → AddSecs4Net() / モデル登録
  │ await Host.StartAsync()
  │    └─ IHostedService.StartAsync()  ← 即座に return (ブロックしない)
  │         └─ バックグラウンドで RunMessageLoopAsync()
  │              ├─ ISecsConnection.Start(ct)  ← HSMS 開始 (Passive=待受 / Active=接続)
  │              └─ await foreach (GetPrimaryMessageAsync)  ← メッセージ受信ループ
  │ MainWindow.Show()  ← UI 表示
```

> **設計上の注意:** `IHostedService.StartAsync` は速やかに return する必要がある。
> 受信ループを `StartAsync` 内で `await foreach` するとホストの起動が完了せず、
> UI ウィンドウが表示されない。このためループはバックグラウンドタスクで実行する。

### 2.6 起動エラーの可視化

ダブルクリック起動ではコンソールが無く、未処理例外が出ても画面に何も表示されずに
終了してしまう。両アプリは以下で起動失敗を可視化する。

- `DispatcherUnhandledException` / `AppDomain.UnhandledException` を捕捉し、
  exe と同じフォルダの `startup-error.log` に追記 + ダイアログ表示。
- ポート使用中 (`SocketError.AddressAlreadyInUse` / WSAEADDRINUSE=10048) を検出し、
  「ポート 5000 は既に使用されています」と原因・対処を明示するダイアログを表示
  (Equipment は Passive で Bind するため起こりやすい)。

### 2.7 接続設定の実行時変更 (UI)

両アプリの「接続設定 (HSMS)」パネルから、IP アドレス・ポート・DeviceId・Active/Passive を
GUI で変更できる。仕組みは以下のとおり。

- 入力値を検証 (`ConnectionSettingsUtil.TryBuild`) し、exe と同じフォルダの
  `appsettings.json` の `secs4net` セクション該当キーのみ更新 (`AppSettingsService.Save`)。
  他セクション (Equipment / Logging) と secs4net 内の他キー (T3〜T8 等) は保持する。
- 保存後、自身を `--restart` 引数付きで再起動 (`StartNewInstance` → `Application.Shutdown`)。
- 再起動側は起動時に `--restart` を検出し、旧プロセスがポートを解放するまで約 1.5 秒待って
  から `HsmsConnection` を Bind する。

> secs4net の接続 (`HsmsConnection`/`SecsGem`) は起動時生成の Singleton であり、稼働中の
> ホットスワップは行わない。設定反映は「保存 → クリーン再起動」方式とし、HSMS 状態機械を
> 毎回まっさらな状態から開始することで確実性を優先している。

### 2.8 シーケンス監視 (想定順序との照合)

実機デバッグ向けに、**想定する SECS メッセージ順序**と**実際の送受信順序**を照合し、
スキップ・順序逸脱・想定外メッセージを一目で確認できる監視機能を両アプリに搭載する。

- **想定シーケンス定義**: exe と同じフォルダの `sequence.json` から読み込む
  (`SequenceLoader`)。無ければ既定 (ONLINE 確立シーケンス) を読みやすい形式で書き出す。
  ```json
  { "name": "ONLINE確立シーケンス",
    "steps": [ { "sf": "S1F13", "desc": "..." }, { "sf": "S1F14", "desc": "..." } ] }
  ```
- **照合ロジック** (`SequenceMonitor`): 送受信したメッセージ (S/F) を時系列順に投入し、
  期待ステップと突き合わせる。
  - 一致 → そのステップを **Done (緑)** + 受信時刻、次を **Active (黄)**
  - 期待より先のステップに一致 → 間の未到達ステップを **Skipped (赤)**
  - 定義に無い／通過済みのメッセージ → **想定外** としてカウント (逸脱扱い)
- **観測点**: Equipment は受信 Primary と送信 Reply (`MessageObserved` イベント)、
  Host は `SendAndLog` (送信/応答) と装置発 Primary (`OnPrimaryMessageReceivedAsync`)。
- UI ヘッダーに `✅完了` / `⚠逸脱検出` / `監視中…次:SxFy` を表示。`[再読込]`/`[リセット]` 可。

> `sequence.json` を編集すれば、ONLINE 以外の任意の手順 (レシピ送信・E87 など) を
> 監視対象にできる。

## 4. GEM 状態機械

### 4.1 通信状態 (Communication State Model)

```
DISABLED
  │ HSMS接続確立
  ▼
WAIT_CR_FROM_HOST ──T7タイムアウト──► WAIT_DELAY
  │ S1F13受信
  ▼
COMMUNICATING
  │ HSMS切断
  ▼
DISABLED
```

| 状態 | 値 | 説明 |
|------|----|------|
| Disabled | 0 | 通信無効 |
| WaitCrFromHost | 1 | S1F13 受信待ち |
| WaitDelay | 2 | T7 タイムアウト後の遅延待ち |
| WaitCr | 3 | CR 送信待ち |
| Communicating | 4 | 通信中 |

### 4.2 制御状態 (Control State Model)

```
EQUIPMENT_OFFLINE
  │ S1F13 (通信確立)
  ▼
ATTEMPT_ONLINE
  │ S1F17 (ON-LINE 要求)
  ▼
ONLINE_REMOTE ◄──S2F41 LOCAL──► ONLINE_LOCAL
  │ S1F15 (OFF-LINE 要求)
  ▼
HOST_OFFLINE
```

| 状態 | 値 | 説明 |
|------|----|------|
| EquipmentOffline | 0 | 装置オフライン |
| AttemptOnline | 1 | オンライン試行中 |
| HostOffline | 2 | ホスト主導オフライン |
| OnlineLocal | 3 | オンライン / ローカル制御 |
| OnlineRemote | 4 | オンライン / リモート制御 |

### 4.3 処理状態 (Processing State Model)

```
INIT → IDLE ⇄ SETUP → READY → EXECUTING ⇄ PAUSE
                                    │
                                  IDLE (完了)
```

| 状態 | 値 | 説明 |
|------|----|------|
| Init | 0 | 初期化中 |
| Idle | 1 | アイドル |
| Setup | 2 | セットアップ中 |
| Ready | 3 | 実行準備完了 |
| Executing | 4 | 実行中 |
| Pause | 5 | 一時停止中 |

### 4.4 ポート状態 (Port State Model / SEMI E87)

| 状態 | 値 | 説明 |
|------|----|------|
| OutOfService | 0 | サービス停止中 |
| InService | 1 | サービス中 (初期値) |
| ReadyToLoad | 2 | ロード準備完了 |
| ReadyToUnload | 3 | アンロード準備完了 |
| TransferBlocked | 4 | 転送ブロック中 |

### 4.5 キャリア状態 (Carrier State Model / SEMI E87)

| 状態 | 値 | 説明 |
|------|----|------|
| Unknown | 0 | 不明 |
| WaitingForHost | 1 | ホスト応答待ち (初期値) |
| InProcess | 2 | 処理中 |
| CarrierComplete | 3 | 処理完了 |
| TransferBlocked | 4 | 転送ブロック中 |

## 8. プロセスプログラム管理 (S7)

### 8.1 データモデル

```csharp
class ProcessProgram {
    string   PpId;          // プロセスプログラム ID
    byte[]   Body;          // レシピボディ (UTF-8 バイト列)
    DateTime LastModified;  // 最終更新日時
}
```

### 8.2 送受信シーケンス

```
Host                                Equipment
 │── S7F1 (PP Load Inquire: PPID) ──►│
 │◄─ S7F2 (PPGNT=0: Granted) ────────│
 │── S7F3 (PP Send: PPID + Body) ───►│
 │◄─ S7F4 (PPACKED=0: Accepted) ─────│
 │                                    │── CEID=201 (ProcessProgramCreated)
```

### 8.3 PPACKED コード

| 値 | 意味 |
|----|------|
| 0 | Accepted |

### 9.1 ロードポート構成

| PortID | 名称 | 初期状態 | アクセスモード |
|--------|------|---------|--------------|
| 1 | LP1 | ReadyToLoad | Auto |
| 2 | LP2 | ReadyToLoad | Auto |

### 9.2 S14F1 GetAttr オブジェクトタイプ

| オブジェクトタイプ | 取得可能な属性 |
|----------------|-------------|
| Port | PortID, PortState, AccessMode, CarrierID |
| Carrier | CarrierID, PortID, CarrierState |

### 9.3 キャリアIN/OUTシーケンス (シミュレーション)

```
Equipment UI操作 (ロードボタン)
  │
  ▼
LoadCarrierAsync(portId, carrierId)
  │ ポート状態: InService → ReadyToUnload
  │ Carriers ディクショナリに追加
  │── S6F11 (CEID=301: CarrierIn) ──► Host
  │── S14F9 (CarrierIn通知) ──────── Host
```

```
Equipment UI操作 (アンロードボタン)
  │
  ▼
UnloadCarrierAsync(portId)
  │ ポート状態: ReadyToUnload → InService
  │ Carriers ディクショナリから削除
  │── S6F11 (CEID=302: CarrierOut) ── Host
  │── S14F11 (CarrierOut通知) ─────── Host
```
